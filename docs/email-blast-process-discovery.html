The manual pipeline

Cyrene walked the room through a live send. Every stage below is a real screen from the call — and most of them are done from a blank slate, every single time.

01

Blast Request

Requester fills a form: states & regions, industries, position levels, and the message itself.

02

Calendar Slot

Cyrene books the send on an Outlook day, spaced ~24h apart per segment so lists don't collide.

Color-coded by hand: yellow (needs list) → purple (built) → red (sent)
03

List Build

A fresh report and a brand-new list, built from nothing — never cloned or reused.

Same segments, rebuilt from zero on every send — "8,000-step process"
04

Template & Sign-off

Ashley ports the Word doc into a Salesforce template, sends herself a test, then forwards it to Mike & Rob.

Approval is an email back-and-forth — no record in the system
05

MassMailer Setup

Target list, template, sender identity, and suppression checks are all picked by hand.

Only 2 suppression filters can combine at once
06

Two-Person Launch

Whoever built the send hands it to Ashley, who re-verifies everything before pressing launch.

07

Apex Queue

Batches process five at a time, roughly twelve sends a day for search alone.

Caps at 5 concurrent batches — one run eats the whole morning

Also broken, per Cyrene: duplicate-send detection, A/B testing, and CC/BCC — none have worked in years. Cross-checks between researchers happen ad hoc in Slack, not in the tool.

what Artemis replaces
The Artemis concept

A targeting engine, not a blast list

Same shape, fewer hands. A list is either already canned or built fresh — either way it resolves to one query, frozen into a static send list the moment it's requested.

Path A

Canned List

A pre-built, reusable segment — e.g. "CA · Real Estate · Executive Search."

Path B

Build New Query

No canned segment fits — build the filter fresh, this one time.

Query, at Time of Request

Whichever path it came from, it runs once, right now — not a live feed that can drift under a scheduled send.

Narrows the query

Targeting Filters

  • Position levelC-suite, VP, Director, Manager…
  • DisciplineHR, Finance, Technology…
  • Company size & revenueright-size the target, both directions

JLL has 75 C-suite contacts — filters pick the right few, never all 75.

↓

Point-in-Time Snapshot

A static clone becomes the send list and the system of record — untouched by anyone added to the segment afterward.

Applied before freezing

Exclusion Layer

A cooldown window (debated: 48h → maybe 24h, maybe none) plus a permanent override — the "never email this person" switch.

↓

Send + Event Tracking

Delivered, opened, clicked — every event ties back to this exact snapshot, forever.

Who's even in the database? Salesforce only kept people worth emailing. Artemis keeps everyone — janitor to CEO — and lets filters do the targeting instead. Doubling the database costs about $300/month; not a reason to prune anyone.
